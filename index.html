Case Study 01 — AI Workflow Audit

Mapping Where AI Helps and Where It Gets in the Way

Problem

I did not know where AI should be used and where it should not. Everyone said "use AI" — but no one explained which tasks it actually helps with and which it gets in the way of.

What I Did

Listed 15 real weekly tasks — CS coursework, internship, side projects. Classified each one honestly: AI only, human only, or collaborate. Wrote one honest reason per task.

Outcome

First time my AI use was intentional — not random. Built a proof statement that is actually mine, not borrowed from a template.

Case Study 02 — Prompt Engineering

From "Help Me With My Code" to a Reusable Debugging Template

Problem

Weak prompts return weak outputs. "Help me with my code" got three questions back — zero actual help. Most people never go further than this.

What I Did

Ran 5 prompt iterations, each adding one named technique: role assignment, context, few-shot examples, output structure, step decomposition. Tested on Claude and ChatGPT.

Outcome

Version 3 failed — proved format without real code is useless. Final template works for any beginner debugging task. Claude followed format strictly; ChatGPT added useful context but broke structure.

Case Study 03 — Automation Workflow

Draft → Critique → Revise: A 3-Step Content Pipeline

Problem

Writing good beginner-friendly technical explanations takes 25-30 minutes manually. Generic AI output without structure is barely better than nothing.

What I Did

Built a 3-step pipeline: Draft → Critique → Revise. Ran 5 topics: Chatbots, APIs, ML, Neural Networks, GitHub. Each run improved critique score from 6/10 baseline to 8/10+.

Outcome

Time dropped from 25 min to 9 min per topic after setup. Honest failure: setup cost is real — pipeline only pays off from topic 2 onwards. Human review still required for accuracy.
